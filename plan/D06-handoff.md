## 5. Working rules

- Commit each finished task locally. The main session's commits end with the attribution lines from the session's system reminder; **subagent briefs say "ending with the trailer your agent instructions specify"** and never dictate a model name. **Never push** unless the user asks.
- The main session edits only plan, evidence and handoff documents. Every task, bug task and code change (including dependency pins) goes to a fresh `tdd-task` subagent. Since the prefactor's retrospective (2026-11-01), the agent definitions hold the working rules every brief used to repeat. `tdd-task.md` covers the Edit tool only, scratch directories, exit codes, browser runs and ports, rebuilding after a mutation, staging, and a clean-tree check after the commit. `suite-runner.md` covers its port checks and waiting for a backgrounded stage. `ocr-review.md` covers the relocated review for test-only commits. Briefs carry only the task-specific parts. `guard-shell-writes.sh` (section 1) refuses shell writes to tracked files and HEAD moves in the worktree, for subagents and the main session alike. The run covers unit, integration and browser suites, plus the static and verify checks: typecheck, `tsc6`, lint, `lint:deps`, build, and every `verify:*` (12 checks at the end of D5). The whole suite takes about 9.5 minutes, near the Bash tool's 10-minute limit, so since 2026-11-01 the runner runs it as four foreground stages (`full-suite.sh <dir> <label> unit|integration|browser|checks`) and never backgrounds or polls. **The browser stage after a task is `browser-auto <base>`** (decision 71, P55), where `<base>` is the commit the task started from. - Every implementation commit gets an `ocr-review` run. **Findings become bug tasks automatically**, as `.claude/docs/implementing.md`, "After each task", says: each Valid or Doubtful finding with a failure scenario becomes `<task>-B<n>`, fixed test-first in a fresh `tdd-task` subagent and reviewed again, one at a time; a Wrong finding, or one with no failure scenario, is dismissed with its reason in `structural.md`. - Refer to document sections in words, never with the "§" sign.
- Lead with a recommendation and its tradeoff. Ask **one consequential decision at a time**, in prose, and include enough context that the question stands on its own.
