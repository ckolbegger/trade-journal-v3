**Provisional means precisely this:** D2–D7 text is read-only in the same way as frozen text — it may
be read, and it may be amended only through §8's errata or adjustment classes — and none of its tasks
may be implemented until §12 confirms the 15 D1 interface seams. Confirmation is expected to be a
one-line register entry; it exists so that a D1 discovery cannot invalidate 121 tasks mid-flight.

### Recorded deviation from `planning-protocol.md:193`

The protocol requires the approved plan to receive the **complete** task graph. It does not: D8–D22
have no task graph, so 35 of 67 scenarios have no task behind them at all and 51 of 67 are not
`covered`. Recording the deviation rather than hiding it, because the alternative — writing 15 more
breakdowns before any implementation — degenerates into plan-maintenance against an unverified
foundation.

**Compensating controls:** every frozen deliverable is dependency-closed; every unfrozen scenario is
named with an owner in the matrix; the interfaces the frozen text depends on are enumerated in §7 and
confirmed before wave 2; and §13 fixes the conditions under which the next freeze may occur. This is a
branch-local sequencing decision, not a claim that the protocol's requirement has been met.

## 8. Change control

Everything D1 discovers falls into exactly one class. The classes exist so that ordinary
implementation reality does not become a re-freeze ceremony.

| Class | Definition | Approval | Recorded as |
|---|---|---|---|
| **Errata** | Pre-declared non-semantic: directory and test-file names, script spellings, version resubstitution within the profile, a missing task citation, a package T1 needs that the profile omitted, comment and cross-reference fixes | None — the plan already declares these mechanical (D4 §3; D1 §8) | Register entry, then manifest re-stamp |
| **Adjustment** | A seam in §7 changes shape while every meaning and every scenario status holds: a different `RuntimeNotWritable` payload field, a renamed manifest key, a merged or split D1 task that keeps the graph valid | One message to the user, and a yes | Register entry naming the affected tasks, then manifest re-stamp |
| **Deviation** | `planning-protocol.md:203`: any durable format, public behaviour, capability scope, scenario status or task-graph order change — e.g. the lifecycle index cannot carry `FactRevision`, or Journal preparation cannot run inside the D1 transaction | Work pauses; affected scenarios and durable compatibility are identified from the matrix; explicit approval; **new freeze revision** | New freeze record revision |

The register is [freeze-errata-2026-10-17.md](freeze-errata-2026-10-17.md). Every entry names its
class, its files, its approver and the timestamp, and every entry ends with the same two validators
plus `shasum -a 256 -c`. An entry that cannot name a class is a deviation by default — resolve the
classification before editing anything.

**Open erratum at freeze time — E-001.** D2, D3, D6 and D7 rely on the persistence-level
`RuntimeNotWritable` rejection (4, 5, 3 and 7 mentions) but none cites `D1:T12`, while every other D1
dependency is cited by id. Apply at wave-2 confirmation: where those files describe the

## 9. Assumptions and remaining non-product risks

1. **Node 26.12.0 is a current major, and it is the pinned runtime rather than a fallback.** No pinned
   package declares it out of range, and pnpm 11.7.0 executes under it, but Vitest-on-26 and
   Playwright-on-26 are only truly proven by D1's own runs: T1 for the toolchain and T20/T33 for the two
   real engines. The other three current majors are TypeScript 7.0.2, Vite 8.3.4 and Vitest 5.0.5. If a
   pair fails, the fallback is resolved at T1 by the same registry query and recorded as an adjustment —
   no fallback version is pre-named here, because naming one without resolving it would be worse than
   leaving it to T1.
2. **Workbox's precache manifest may not be a usable digest-valid inventory.** D1:T16 therefore asserts
   its own digests over built bytes and T17 hashes the cached bytes at runtime. If the toolchain later
   supplies equivalent evidence, the custom instrumentation may shrink, but not be dropped (D1 §8).
3. **The capacity minimum is plan-derived, not measured** against a real 25,000-Trade Workspace,
   because no deliverable builds that dataset. A too-high minimum surfaces as `Unsupported` on a healthy
   browser; the terms are auditable in one place.
4. **`fake-indexeddb` fidelity gaps** — abort/durability ordering, multi-store atomicity under a shared
   transaction handle, index key ordering, write-gate interaction, quota and eviction — are disclosed
   with real-engine counterparts (D1 T9.4, T11.6, T18.3, T18.4, T20, T33; D4 T25; D6 T19; D7 T13).
5. **No production HTTPS origin exists or is owned.** `AC-DEL-003` requires production HTTPS evidence;
   loopback is not a substitute. Carried to C-5.
6. **Runtime Readiness evidence uses two engines.** Firefox is cached but is not evidence; adding it is
   an evidence change, not a support decision.
7. **pnpm is environment state, not repository state**, installed globally because corepack is not part
   of this Node distribution. A machine rebuild breaks every recorded command until it is reinstalled
   (§2), and the `packageManager` field cannot enforce the version on its own — D1:T1 must assert
   `pnpm --version` and `pnpm exec node --version` instead of trusting the field.
8. **No CI.** All evidence is produced locally on an unpushed branch; nothing verifies the evidence
   exists except the recorded commands and this plan's gates.
9. **The foreign stash** (`stash@{0}`, another worktree's in-flight work) must never be applied, popped
   or dropped. It is visible only because the worktrees share one object store.
10. **A Partial coverage row is never a pass.** 51 rows are `planned`; only the 16 `covered` rows are
    defended at this freeze.
11. **Date and Money round-trips are asserted at the byte level**: stored amounts are decimal strings,
    never JS `number`, and no floating-point drift is tolerated across serialization (D2:T6, D3:T4).
