# Trade Journal V3 — acceptance-to-evidence matrix (draft, Phase 4)

This is the traceable Phase 4 companion to `plan/vertical-deliverable-plan.md`. It has one row per acceptance scenario in `specs/acceptance/acceptance-contract.md`, including the two new scenarios `AC-REV-007` and `AC-IV-001`. Nothing is implemented yet, so every status is `planned`; `covered` replaces it only when the named commands and evidence have actually been run and recorded.

## Environment and provenance

- **Stack:** TypeScript 7.0.2 via `@typescript/native` (`npx tsc`), `@typescript/typescript6` alias for typescript-eslint (`npx tsc6`), React + Vite, IndexedDB, `decimal.js`, injected clock and explicit U.S. trading calendar.
- **Typecheck:** `npx tsc --noEmit` and `npx tsc6 --noEmit`; **lint:** `npm run lint`.
- **Browser automation origin:** `http://localhost:$DEV_PORT` (worktree port 5182), used only when the tested browser recognises loopback as a secure context for service-worker and storage behaviour. This does **not** replace production HTTPS evidence.
- **Production evidence:** a deployed HTTPS origin must record Web App Manifest, Offline Release Inventory, service-worker control and install/browser-tab launches. Exact browser and OS versions are recorded as evidence provenance, never as a support allowlist.
- **Disclosed test infrastructure:** `fake-indexeddb` for integration tests; isolated dependency instances are permitted, but no application layer or production contract may be bypassed by a mock.

## Command conventions

Cells use these templates with a family name substituted:

- `U(family)` = `npx vitest run tests/unit/<family>.test.ts -t "<behaviour named in the cell>"`
- `I(family)` = `npx vitest run tests/integration/<family>.test.ts` with the fixture named in the cell
- `B(family)` = `npx playwright test e2e/<family>.spec.ts` against `http://localhost:$DEV_PORT`
- `S(...)` = the explicit structural command written in the cell

Structural tasks state their exact verification rather than invented `describe`/`it should` cases.

## Secrets exclusion and no-write verification

- **Secrets exclusion:** `AC-BACK-001` and `AC-DEL-003` evidence includes automated scanning of every exported artifact for provider credentials, raw payloads, diagnostics, report caches and private projections, plus a manifest of explicit exclusions. Restore resets configured providers to `Needs Setup`.
- **No-write and rollback:** every scenario expecting no write records authoritative snapshots of all four fact sections and Workspace metadata immediately before and after the attempt, compares digests and revisions, then restarts the application and repeats the relevant query. Failure-injection cases record the injected failure, the rolled-back before-state and the eventual successful retry.

## Intentionally not advertised

No acceptance scenario is waived. Capabilities outside the MVP — account snapshots, cash reconciliation, equity curves, provider-performance analytics, custom date ranges, nested grouping, general report builder, automatic coaching, LLM judgment, interpretive Insights and Future Insights — have no declared acceptance scenario and must remain absent from navigation, the Installed Capability Manifest and the UI. The advisory IV exception is declared under `AC-IV-001` only.
