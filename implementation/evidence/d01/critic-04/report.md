## Fault mechanics and durable proof

Native infrastructure faults preserve the production application path. Transaction failure aborts a real native readwrite transaction; capacity uses a **lowered** StorageManager prototype estimate of zero only for failure cases; control uses a ServiceWorkerContainer controller getter returning null; inventory cases physically corrupt/delete Cache Storage responses and restore exact original bytes afterward. All-four tests combine these mechanisms. No override is used to make a failing host pass.

Unreadable-root faults throw SecurityError only from actual roots-store read methods, while a clean tab observes existing bytes. Plan/Journal aborts attach a success listener to the native versions-store request and abort its encompassing transaction. The verified Plan-stage repeat and both keyboard Journal-stage repeats use one abort. One initial Journal harness wrapper called abort twice and generated an injected InvalidStateError; it is retained in console evidence and is not an application defect.

Loading uses a real lifecycle-store transaction held open with repeated **reads**, with zero writes; normal list query blocks behind it. The verified Error case throws UnknownError from native lifecycle index `openCursor`, after ordinary startup, then reload clears the fault. `a11y-error` was an initial ineffective selector attempt and was excluded from the final twenty-state summary; `a11y-error-verified` is the actual Error evidence.

Normalized raw native database snapshots cover roots, immutable versions, lifecycle, projections and diagnostic store. Empty diagnostic store is retained in snapshots. Data was never inserted directly to simulate an accepted Trade/reference/Journal capability.
