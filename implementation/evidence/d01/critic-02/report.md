## F01 — distinguish the existing complementary landmarks (P2)

Replace only the native `navigator.storage.estimate` function with a rejected promise to represent the required late capacity API failure. Click Confirm Plan. The application correctly enters Recovery Only and preserves the draft and authoritative state, while the actual DOM contains two unnamed `<aside>` complementary landmarks: Recovery Only and the BestEffort storage advisory.

Expected: the planned B05 axe/manual accessibility-tree checks produce distinguishable landmark roles/names. The UI contract requires coherent programmatic names/roles/states and accessibility-tree operation; the D1 plan T08/B05 requires manual tree and axe checks for installed recovery/error states.

Actual: axe4.13.0 reports **landmark-unique**, moderate, `cat.semantics`/`best-practice`, target `aside:nth-child(3)`: “The landmark must have a unique aria-label, aria-labelledby, or title to make landmarks distinguishable.” Both landmarks are anonymous in the accessibility tree. This is a concrete semantic accessibility defect; the axe rule is a best-practice rule, **not a claim of a WCAG-AA contrast criterion violation**. The same anonymous-aside pattern also exists for Update available; that combination was not separately axe-tested here.
