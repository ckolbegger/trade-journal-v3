# TypeScript 7 and typed ESLint compatibility

Research date: **2026-10-18**. Scope: planning evidence for Node **26.12.0**, npm **11.20.0**, React **19.3.0**, and TypeScript **7.0.2**. Registry manifests and package-source text were read without installing dependencies or executing downloaded code. The npm resolver probe below used the already installed npm. No application scaffold, package manifest, lockfile, or tests were created.

## Alias and version routing

Microsoft explicitly recommends these two aliases because TypeScript 7.0 lacks the compiler API used by typescript-eslint. Its intended routing is `tsc` → TypeScript 7 and `tsc6` → the legacy compiler. The versions above replace the announcement's ranges with exact direct specifications. [Microsoft announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

The wrapper **6.0.2** is not the underlying compiler API version. Its manifest depends on `@typescript/old: npm:typescript@^6`. The published source forwards `lib/typescript.js` and `lib/tsserverlibrary.js` to `require("@typescript/old")`; `lib/tsc.js` forwards to `@typescript/old/lib/tsc.js`. The current stable legacy compiler is **6.0.3**. Require the future committed lockfile to resolve this transitive alias to exactly `typescript@6.0.3` and record its integrity; do not add a direct `@typescript/old` dependency or peer override. [Wrapper manifest](https://registry.npmjs.org/@typescript/typescript6/6.0.2), [wrapper source archive](https://registry.npmjs.org/@typescript/typescript6/-/typescript6-6.0.2.tgz), [legacy compiler manifest](https://registry.npmjs.org/typescript/6.0.3).

The native package's shipped `bin/tsc` is a Node launcher (`#!/usr/bin/env node`, importing `../lib/tsc.js`). Set the future typecheck command explicitly to `node node_modules/@typescript/native/bin/tsc -b`, so compiler selection does not depend on an executable collision. The legacy compiler also publishes `tsc`; if hoisted, its transitive alias can contend for the root binary. npm 11.20.0 sorts bin linking by depth/path and keeps the first target, making Microsoft's `@typescript/native` name precede `@typescript/old` in the ordinary layout, but actual routing must still be verified. [Native source archive](https://registry.npmjs.org/typescript/-/typescript-7.0.2.tgz), [npm bin queue](https://github.com/npm/cli/blob/v11.20.0/workspaces/arborist/lib/arborist/rebuild.js), [first-target handling](https://github.com/npm/cli/blob/v11.20.0/node_modules/bin-links/lib/link-gently.js).

## npm peer resolution evidence and remaining gate

npm supports aliases in dependency specifications. Its resolver uses the installed alias location name to match an edge, then semver-checks the package version; alias dependency specifications recurse to their target specification. A read-only, in-memory probe using installed npm **11.20.0** parsed `typescript: npm:@typescript/typescript6@6.0.2` and constructed its ordinary TypeScript peer edge. Result: location name `typescript`, actual package name `@typescript/typescript6`, wrapper version `6.0.2`, peer range `>=4.8.4 <6.1.0`, `peerValid: true`, `peerError: null`. Thus the different published package name does not itself require `--legacy-peer-deps`, `--force`, or an override. [npm alias semantics](https://docs.npmjs.com/cli/v11/using-npm/package-spec/#aliases), [edge matching](https://github.com/npm/cli/blob/v11.20.0/workspaces/arborist/lib/edge.js), [dependency validation](https://github.com/npm/cli/blob/v11.20.0/workspaces/arborist/lib/dep-valid.js).

This establishes metadata/resolver compatibility, not a completed install. After implementation authorization, create the exact lockfile normally, then require ordinary **`npm ci`** to succeed with no peer bypass and no overrides. Verify the transitive compiler/API, native platform package, and executable routing from that installed tree. `npm ci` requires an existing consistent lockfile and does not update it. [npm ci documentation](https://docs.npmjs.com/cli/v11/commands/npm-ci/).

## Typed flat configuration and file coverage

Use `defineConfig` from `eslint/config`, `js.configs.recommended`, and `tseslint.configs.recommendedTypeChecked`, scoped to `**/*.{ts,tsx,mts,cts}`. Set `languageOptions.parserOptions.projectService: true` and `tsconfigRootDir: import.meta.dirname`. `recommendedTypeChecked` already includes the ordinary recommended rules. Apply browser globals to browser code and Node globals to tooling/configuration files as applicable. Keep JavaScript configuration under a separate untyped recommended block. Ignore generated build, coverage, Playwright report, and test-result outputs. [Typed linting setup](https://typescript-eslint.io/getting-started/typed-linting/), [shared preset semantics](https://typescript-eslint.io/users/configs/), [extension/configuration guidance](https://typescript-eslint.io/getting-started/).

All installed TS/TSX must be covered: application and worker sources, Vite/Playwright/Vitest configuration, tools, test setup, unit/integration/browser/benchmark tests, and TSX test fixtures. Use discoverable `tsconfig.json` files or a root solution whose project references cover those files. Project Service supports references; merely adding an unreferenced `tsconfig.eslint.json` is insufficient because automatic discovery recognizes `tsconfig.json`/`jsconfig.json`. Prefer explicit project inclusion over `allowDefaultProject`; the latter forbids `**`, cannot overlap an included file, defaults to eight files, and adds overhead. Do not combine `project` and `projectService` as a workaround. [Project discovery and references](https://typescript-eslint.io/troubleshooting/typed-linting/), [Project Service options](https://typescript-eslint.io/packages/parser/#projectservice).

T01 must inspect effective ESLint configuration for representative application TS, TSX, worker, test, and tooling files, then demonstrate that a temporary type-aware violation such as an unhandled `Promise.resolve()` is rejected by `@typescript-eslint/no-floating-promises`; remove it and rerun lint. Strict TypeScript 7 checking remains a separate gate. Verify local `tsc --version` → **7.0.2**, `tsc6 --version` → **6.0.3**, the explicit native command → **7.0.2**, wrapper package metadata → **6.0.2**, and `require("typescript").version` plus the wrapper-resolved `@typescript/old` API → **6.0.3**. These are future acceptance checks, not results claimed by this research.
