## 3. Overall: **PASS**

### Defects

**1. The counts table splits words and numbers mid-word at 375 and 320 px. Severity: low.**
- **Steps:** Open any Restore preview over a journal with data, then narrow the window to 375 or 320 px. See `shots/c83-confirm-375.png` and `shots/c83-confirm-320.png`.
- **Expected:** text that wraps cleanly on narrow screens (UI contract on responsive layout, AC-UI-001).
- **Actual:**
  - At 375 px, the "In the backup" heading breaks as "backu / p", and "3 (14 versions)" breaks as "3 (14 / version / s)".
  - At 320 px it breaks as "In / the / back / up" and "versi / ons".
  - On first run, a ")" sits alone on its own line.
  - The figures can still be read, and the page does not scroll sideways.

**2. Wrong plural "1 (1 versions)". Severity: low.**
- **Steps:** Open a Restore preview over a journal that holds one Journal entry. See `shots/c84-decline-wide.png`.
- **Actual:** the "Journal entries" row shows "1 (1 versions)". The approved wording is "(N versions)", and it isn't adjusted for one.

## 4. Minor observations
- **Empty candidates list left in the root:** after a preparation, the root keeps `{ key: 'candidates', databaseNames: [] }`. That was the only root difference after C8.6's failed apply. It is already known (the support module's `withoutEmptyCandidateList`).
- **Focus after Restore:** once Restore succeeds, keyboard focus drops to `<body>`, on both the Backup page and first run. It doesn't move to the "Restore complete" heading or to "Go to Trades".
- **No way back:** after "Restore from a backup" on first run, and on any preview, there is no Cancel or Back. The trader can return to "Start my journal" only by reloading.
- **Acknowledgment stays ticked:** if the trader ticks the decline acknowledgment, switches to "Back up this journal first" and then back to decline, the box is still ticked. Replace is enabled again without a fresh acknowledgment.
- **Apply-failure wording:** an injected journal-entries recheck failure reads "The checked backup is no longer available." That is the approved wording, but it only loosely describes what happened.
- **"Backup complete" without a time:** in Migration Blocked the line has no "Checked …" time, and it sits above the buttons that produced it.
- **"Not verified yet" with nothing to verify:** while waiting to convert, the download says "Downloaded, not verified yet…" although Verify is deliberately not offered. Approved by Q2, part C.
- **Release shown as a hash:** the preview shows the release as a 64-character hash, where Q2's A4 example used a dated release ("release 2026.11.14"). It now wraps without overflow.
- **Reflections owed:** the row shows "(N versions)", for example "0 (0 versions)". Where version counts appear is still open in Q8.
- **About's Entry Types line** uses internal keys ("entry-type.plan-reflection"). It also lists the manifest's Strategy keys, so this is likely intentional.
- **Section headings:** they are lower-case in the page and shown upper-case by styling ("restore needs a browser that can save safely"). Purely visual.
